# Design: E-mail text blocks

## Context

Post templates (`EmailTemplate`) are XML files on the server, managed in
`EmailTemplatesPanel` and applied via `cmbTemplatesActionPerformed` in `SendEmailFrame` and
`SendBeaMessageFrame`, which replaces the whole message. Both composers use the
`EditorImplementation` abstraction: `TextEditorPanel` (JTextArea) and, in `SendEmailFrame`
only, `WebViewHtmlEditorPanel` (SunEditor in a JavaFX WebView). Both implementations already
support inserting at the cursor: `TextEditorPanel.insert(text, pos)` and
`WebViewHtmlEditorPanel.insert(html, pos)`, which calls SunEditor's `insertHTML` at the
current selection (the position argument is ignored). The signature button
(`cmdInsertSignatureActionPerformed`) uses exactly this mechanism.

Settings entries in the "Vorlagen" popup of the module bar are generated by
`ModuleBar.addModule` from modules flagged with `setSettingsEntry(true)` in `Main.java`; the
label is "<module name>: <editor name>".

## Goals / Non-Goals

Goals:
- Maintain named text blocks with plain-text and HTML variants and an optional folder path.
- Insert a text block at the cursor of the e-mail and beA composer via a hierarchical menu.
- Resolve placeholders on insert with the same context as post templates.

Non-Goals:
- Personal / user-specific text blocks or per-block permissions.
- REST API endpoints for text blocks.
- Import/export of text blocks.
- Keyboard shortcuts or auto-text expansion while typing.
- Using text blocks in other editors (documents, notes, instant messages).
- Migrating existing post templates into text blocks.

## Decisions

### Storage in the database
Text blocks are stored in a new table instead of files. A single query returns all blocks for
the insert menu, uniqueness can be enforced by the database, and backups/replication are
covered by the existing database handling.

Table `text_blocks`:

| Column         | Type                     | Notes                                   |
|----------------|--------------------------|-----------------------------------------|
| `id`           | `VARCHAR(50) BINARY` PK  | generated id, as for other entities     |
| `name`         | `VARCHAR(250)` not null  | utf8mb4                                 |
| `folder`       | `VARCHAR(1000)` null     | normalized path, null = top level       |
| `content_text` | `MEDIUMTEXT` null        | plain-text variant, utf8mb4             |
| `content_html` | `MEDIUMTEXT` null        | HTML variant (body fragment), utf8mb4   |

Uniqueness of folder + name is checked in the service (a unique index on long utf8mb4 columns
exceeds MySQL index limits) by loading the blocks with the same name (`TextBlock.findByName`);
the service treats `null` and empty folder as the same.

Entity name `TextBlock` without "Bean" suffix (convention for new entities).

### Folder path semantics
- Separator is `/`. On save the server trims each segment, removes empty segments and joins
  them again; an empty result is stored as `null`.
- Comparisons (uniqueness, menu grouping) are case-sensitive on the normalized path.
- There is no separate folder entity: folders exist implicitly through the blocks using them.
  The maintenance panel offers the distinct existing folder paths in an editable combo box.

### Service API
Methods are added to `IntegrationServiceRemote`/`IntegrationService`, where the post template
methods live, secured with `@RolesAllowed("loginRole")`. No separate service bean is
introduced for five CRUD methods.

### Content on demand
There may be many text blocks, some with large HTML content (e.g. embedded images). Building the
menu or the maintenance list must therefore not transfer content:
- `getTextBlockSummaries()` returns `TextBlock` objects built by the projection
  `TextBlock.findAllSummaries` (`SELECT NEW ... (id, name, folder, CASE WHEN content_text IS NULL
  ..., CASE WHEN content_html IS NULL ...)`), sorted by folder and name. Their content is null; two
  `@Transient` flags make `hasText()`/`hasHtml()` answer from the database instead of the content.
- This works because the server stores a variant without visible content as `NULL`
  (`TextBlock.isTextContent` / `isHtmlContent` on save).
- A projection, unlike loading entities and clearing their content, never yields managed entities
  whose clearing could be written back (see `NamedQueryProjectionTest`, which now also covers
  `TextBlock`).
- The content of one block is loaded with `getTextBlock(id)` when the user picks it in the menu or
  selects it in the maintenance list.

The client loads the summaries freshly each time the insert menu is opened so changes by other
users are visible without restart.

### Maintenance UI
`EmailTextBlocksPanel` is a main-pane editor like `EmailTemplatesPanel` (not a dialog), so it
fits the existing settings-entry mechanism. Both variants are edited side by side in two tabs
"Text" and "HTML"; the HTML tab uses `WebViewHtmlEditorPanel`. The placeholder list and the
insert action are reused from `EmailTemplatesPanel` (`PlaceHolders.getAllPlaceHolders`,
`PlaceHolders.insertAt`) and insert into the editor of the active tab.

### Hierarchical menu
`TextBlocksMenuBuilder.build(List<TextBlock>, boolean html, Consumer<TextBlock> onSelect)`
returns a `JPopupMenu`:
- each folder segment becomes a `JMenu` with the blue folder icon
  (`/icons16/material/baseline_folder_blue_36dp.png`), created on demand per level
  (generalising the single-level `AssistantAccess.findOrCreateSubMenu` to a recursive tree);
- on every level sub menus come first, then text blocks, both sorted alphabetically
  (case-insensitive);
- a block without the variant required by `html` is added disabled;
- with no text blocks at all, a single disabled entry "keine Bausteine vorhanden" is shown.

### Inserting
- `SendEmailFrame`: toolbar button `cmdInsertTextBlock` after `cmdInsertSignature`. The
  active editor is `(EditorImplementation) contentPanel.getComponent(0)`. Text mode inserts
  the plain-text variant at `tp.getCaretPosition()`, HTML mode inserts the HTML variant via
  `hp.insert(html, 0)` (cursor position of SunEditor), stripping head/body tags with
  `HtmlUtils.stripHeadAndBodyTags`.
- `SendBeaMessageFrame`: toolbar button after `cmdSaveDraft`; always plain text since the
  frame only has a `TextEditorPanel`.
- If text is selected, the inserted block replaces the selection: in text mode the selection
  is removed before inserting at its start, in HTML mode SunEditor's `insertHTML` replaces the
  selection natively.

### Placeholder resolution
The context collection currently embedded in `cmbTemplatesActionPerformed` (party triplets
from `pnlParties`, case lawyer/assistant, author, dictation sign, form placeholder values) is
extracted into a private method in each frame returning the placeholder values for a given set
of texts. Post templates and text blocks both use it:
1. `TemplatesUtil.getPlaceHoldersInTemplate(content, allPartyTypesPlaceholders, formPlaceHolders)`
2. `SystemManagementRemote.getPlaceHolderValues(...)`
3. `TemplatesUtil.replacePlaceHolders(content, values)`; `{{CLOUD_LINK}}` added in
   `SendEmailFrame` as today.

Without case context, placeholders are resolved with whatever values are available (as for
post templates). `{{CURSOR}}` is removed; in text mode the caret is set to its position
relative to the insert offset, in HTML mode it is only removed.

## Risks / Trade-offs

- **SunEditor focus.** Clicking the toolbar button moves the focus out of the WebView. SunEditor
  keeps its last selection range, so `insertHTML` still inserts at the last cursor position;
  if the editor never had focus, the block is inserted at the start. Acceptable, verified
  during manual testing.
- **macOS caret.** `WebViewHtmlEditorPanel.getCaretPosition` returns 0 on the EDT on macOS;
  not relevant because HTML insertion relies on the SunEditor selection, not on an offset.
- **Global maintenance.** Every user can change or delete every block. Matches post templates;
  per-block permissions are a non-goal.
- **Server roundtrip on every menu open.** One query returning only names and folders; the
  content of the chosen block costs a second roundtrip on insert. Acceptable.

## Migration Plan

One Flyway migration creating `text_blocks`; no data migration. Rollback: drop the table.
